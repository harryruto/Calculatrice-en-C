## Calculator

Merci de votre intérêt pour Calculator ! Les contributions sont les bienvenues. ❤️

# 🇬🇧 ENGLISH

## 1. Before Contributing

Before making a contribution, please:

* Check whether an issue or pull request already exists for the same subject.
* Read the project's documentation.
* Make sure your contribution is related to Calculator.
* Follow the project's Code of Conduct.

## 2. Reporting Bugs

When reporting a bug, please provide:

* A clear description of the problem.
* The steps required to reproduce it.
* The expected behavior.
* The actual behavior.
* The version of Calculator being used.
* Any relevant error messages.

Please avoid opening duplicate issues when the problem has already been reported.

## 3. Suggesting Features

Feature suggestions are welcome.

A feature request should explain:

* What the proposed feature does.
* Why it would be useful.
* How it could fit into Calculator.
* Any relevant examples.

The maintainers may review the proposal before deciding whether it fits the project.

## 4. Code Contributions

When submitting code:

* Keep the code readable and understandable.
* Follow the existing coding style where possible.
* Avoid unnecessary changes unrelated to your contribution.
* Test your changes before submitting them.
* Make sure your changes do not introduce obvious errors.
* Clearly explain what your changes do.

## 5. Pull Requests

Pull requests should:

* Have a clear title.
* Explain what was changed.
* Explain why the change was made.
* Include relevant information about testing.
* Contain only changes related to the proposed contribution when possible.

A maintainer may request changes before the pull request can be accepted.

## 6. Commit Messages

Please use clear and descriptive commit messages.

For example:

```text
Add percentage calculation
Fix division by zero handling
Update documentation
```

Avoid messages that do not explain the purpose of the commit, such as:

```text
stuff
test
update
aaa
```

## 7. Documentation

Documentation contributions are welcome.

If you modify a feature, consider updating the relevant documentation so that it remains consistent with the software.

## 8. External Code and Resources

If your contribution uses code, libraries, documentation or other resources created by someone else:

* Make sure their use is permitted.
* Respect the applicable license.
* Give appropriate credit.
* Do not submit someone else's work as your own.

## 9. Review Process

Contributions may be reviewed by the project maintainers.

A contribution may be:

* Accepted.
* Accepted after requested changes.
* Rejected if it does not fit the project or does not meet its requirements.

## 10. Getting Help

If you need help with a contribution, you can contact the project maintainer.

# 🇫🇷 FRANÇAIS

## 1. Avant de contribuer

Avant de proposer une contribution, veuillez :

* Vérifier qu'une issue ou une pull request concernant le même sujet n'existe pas déjà.
* Lire la documentation du projet.
* Vous assurer que votre contribution concerne Calculator.
* Respecter le Code de conduite du projet.

## 2. Signaler un bug

Lors du signalement d'un bug, veuillez fournir :

* Une description claire du problème.
* Les étapes permettant de reproduire le problème.
* Le comportement attendu.
* Le comportement réellement observé.
* La version de Calculator utilisée.
* Les éventuels messages d'erreur pertinents.

Évitez de créer des issues en double lorsqu'un problème a déjà été signalé.

## 3. Proposer une fonctionnalité

Les propositions de fonctionnalités sont les bienvenues.

Une proposition devrait expliquer :

* Ce que fait la fonctionnalité proposée.
* Pourquoi elle serait utile.
* Comment elle pourrait s'intégrer à Calculator.
* Des exemples pertinents si nécessaire.

Les responsables du projet peuvent examiner la proposition avant de déterminer si elle correspond au projet.

## 4. Contributions de code

Lors de l'envoi de code :

* Gardez un code lisible et compréhensible.
* Respectez autant que possible le style de code existant.
* Évitez les modifications inutiles qui ne sont pas liées à votre contribution.
* Testez vos modifications avant de les envoyer.
* Assurez-vous que vos modifications n'introduisent pas d'erreurs évidentes.
* Expliquez clairement les modifications effectuées.

## 5. Pull Requests

Les pull requests doivent :

* Posséder un titre clair.
* Expliquer ce qui a été modifié.
* Expliquer pourquoi la modification a été effectuée.
* Fournir les informations pertinentes concernant les tests.
* Contenir, lorsque cela est possible, uniquement les modifications liées à la contribution proposée.

Un responsable peut demander des modifications avant l'acceptation de la pull request.

## 6. Messages de commit

Utilisez des messages de commit clairs et descriptifs.

Exemples :

```text
Add percentage calculation
Fix division by zero handling
Update documentation
```

Évitez les messages qui n'expliquent pas le but du commit, tels que :

```text
stuff
test
update
aaa
```

## 7. Documentation

Les contributions à la documentation sont également les bienvenues.

Si vous modifiez une fonctionnalité, pensez à mettre à jour la documentation correspondante afin qu'elle reste cohérente avec le logiciel.

## 8. Code et ressources externes

Si votre contribution utilise du code, des bibliothèques, de la documentation ou d'autres ressources créées par une autre personne :

* Vérifiez que leur utilisation est autorisée.
* Respectez la licence applicable.
* Donnez le crédit approprié à leurs auteurs.
* Ne présentez pas le travail d'une autre personne comme étant le vôtre.

## 9. Processus de vérification

Les contributions peuvent être examinées par les responsables du projet.

Une contribution peut être :

* Acceptée.
* Acceptée après modifications demandées.
* Refusée si elle ne correspond pas au projet ou ne respecte pas ses exigences.

## 10. Besoin d'aide

Si vous avez besoin d'aide concernant une contribution, vous pouvez contacter le responsable du projet.

**Contact :** harryruto

**Discord officiel :** https://discord.gg/sgVApZ8eva
